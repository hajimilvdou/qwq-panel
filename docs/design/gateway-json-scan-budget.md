# 网关 JSON 字段与深度预算

范围 OPT-03 的字段/深度检查。真实插件 DTO 基线：512 项、52162 B 正文，每次解码分配 1144864 B、30621 次。原路径对合法正文分别做深度预扫和递归 Token 字段扫描；Token 为字符串值与数字创建大量临时值，原字段路径也为不含对象的普通值分配字符串。

合法请求先复用标准库 `json.Valid` 验证语法，再以单遍字节状态机同时检查容器层级和重复字段。状态机只消费已经确认合法的结构，不自造 JSON 语法或数字规则；仅字段名进入已见表，普通值不生成 Token，只有容器路径或重复字段需要 JSON Pointer。转义字段名或非法 UTF-8 仍由标准 `json.Unmarshal` 规范化，保持代理对的合并、替换字符和字段唯一性行为。

字段表统一由 `sync.Pool` 复用；每个容器关闭或请求出错时清空，超过 128 字段的表不回池，避免单个大对象长期占据复用预算。容器栈受调用方深度限制，不递归遍历合法正文。之后的形状检查、完整 DTO 解码、未知成员/数字/自定义解码器行为保持原链路。

畸形 JSON 与拒绝路径复用原标准 Token 扫描和廉价深度扫描，保留结构错误、深度超限与早期重复字段的原优先级；合法请求不再独立预扫深度。此回退只为错误契约，不授权错误正文进入形状或 DTO 解码。

Linux 验证包含原字段/转义/数组/Pointer/字节/深度用例、结构与深度优先级、标准 Unicode 名称正负对照、32 并发混合请求；33 定向/种子 pass、无 fail/skip。原 Token 链作为独立参照的 10 秒 fuzz 执行 34265 次通过；三包普通、gateway race、静态检查、仓库 lint 和宿主构建均通过，三份 Go 格式按 SHA/成员/token 受检恢复。

同机每种样本各测三次，以下取中位数；B/op 是累计分配字节，不是驻留峰值。

| 项数 / 正文 B | ns/op 前 → 后 | B/op 前 → 后 | allocs/op 前 → 后 |
| --- | --- | --- | --- |
| 8 / 848 | 131424 → 103279 | 20513 → 16890 | 535 → 336 |
| 64 / 6502 | 908538 → 711081 | 147677 → 116266 | 3798 → 2364 |
| 512 / 52162 | 6746640 → 5225270 | 1144864 → 928350 | 30621 → 19330 |

本批实测耗时减少约 21-23%、分配字节约 18-21%、分配次数约 37-38%，不把施工包的 65% 预估写成实测结果。后续形状/DTO 解码仍执行原规则，完整解码路径与 1C1G 峰值继续随总体资源验收核对。

Root 自检：P0 标准语法、规范化字段唯一性和 DTO 前拒绝保持；P1 字节状态机与原 Token 参照通过，错误优先级和当前接口不变；P2 字段表清空/128 项保留上限与并发 race 通过，无后台进程。未见本批新增阻断项。
