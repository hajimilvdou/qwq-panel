# 监控资源选择与历史指标

PLG05 的单调采样与回拨基线已集成 cb2cd71。当前磁盘主指标只读取 /，显式配置其他挂载点仍不可用；网卡先全局验证再过滤，未选中坏名字和默认 veth/tun 瞬态启停会使物理速率为空；history 校验 metric 却不筛选，snapshot 没有多挂载点阈值状态。

复用有限 Point/环、配置校验、派生函数与 threshold。主磁盘优先已配置的 /，否则 cfg.DiskMounts[0]；快照仅按配置顺序公开全部选中挂载点、使用百分比和现有 warn/crit 状态，缺失不伪造零。显式网卡先过滤再校验选中项，默认忽略瞬态 veth/tun，仍严格检查真实目标消失/重置和重复。历史筛选只修改环的副本并保留原完整默认响应。快照 JSON schema 与产出同步，继续原大小上限和只读授权。

首轮只写五类后端 RED，先取得真实失败再实施；UI 曲线 null 断点与范围切换排队随后单独检查，不能将后端子项或全部监控直接勾选完成。

快照使用本地 `$defs/point` 共用当前点与历史点的原契约；新增 `disks` 数量仍受配置的 32 项上限约束，并同步发布清单摘要。阈值沿用原配置，不增加另一套状态或告警规则。追加首次采样、缺失挂载点、实际主磁盘微件和显式虚拟网卡计数回归，验证缺失不变成零、默认过滤不影响显式选择。

UI 使用每条指标独立的 SVG path M/L 分段，在 null 后重新起笔；`pendingRefresh` 将忙碌期间的请求合并为一个最新范围补读。每次刷新固定原范围，两个异步边界重新核范围、暂停、可见性和端口；过期响应不重绘，页面关闭仍回收请求、定时器和端口。主挂载点由宿主快照的 `primary_disk_mount` 明确提供，前端只显示它，不复制选择规则；长挂载点可换行，避免小屏溢出。

验收采用 Linux 定向与完整 monitor 测试、race、vet/staticcheck、仓库 lint 和插件构建。UI 回归在 Node 中直接运行实际页面脚本和 HTML 形状，控制宿主响应时序，验证空值、十次点击、过期范围、暂停/可见性、超时迟到响应和卸载；它不替代真实浏览器或双 VPS 终验。最终十轨、双 VPS 与 1C1G 24 小时终验仍按原执行表推进。
