# Core 换端口前预检

已有原生 `xray -test` 只校验配置语法，不检查真实监听；当前事务会先 StopOld，候选启动时才发现端口冲突。预检必须放在 StopOld 之前，失败保持旧私有快照、宿主 running/current 和健康进程不变。

复用现有 v1 Intent 校验、Summary、真实 Process Snapshot 与失败补偿，不改固定进度步骤。启用候选先尝试绑定实际 TCP 地址并立即关闭探针；禁用候选不请求监听。相同端口的地址变化不能仅按端口号跳过：只有旧已提交摘要和仍匹配的运行代次、内核监听 inode 与原 PID 归属都确认后，才允许排除旧进程自身的精确监听。地址范围扩大时仍检查其他冲突监听。地址族重叠复用 SDK 已有监听规则。

Linux 读取当前网络命名空间与原进程的 `/proc` 只读事实；读不到或事实变化时明确拒绝，不申请额外权限。通配监听用短时空闲端口探针确认当前内核的实际绑定族，再复用 SDK 的双栈重叠规则；旧通配配置呈现为内核另一族通配地址时仍须逐 inode 核原 PID。探针只反映当时可用性，外部进程随后抢占仍由原启动失败补偿处理。真实目标端口占用、首次启动占用、同端口扩大地址时的外部监听是首轮回归；自有监听、无冲突地址变化、禁用与探针关闭补正向验证。X11 真实数据连接与长时终验保持独立未完成。
