# Core 回滚预算与健康数据面保护

P1-PLG-02：现有补偿总预算 10 秒小于 Stop、Restore、Start、健康检查与宿主 CAS 的组合预算；恢复的旧进程已通过健康和摘要核验、私有快照提交与 MarkCommitted 后，宿主 KV 超时仍被通用失败处理停掉。

总预算调整为有界 25 秒，继续保留原调用身份和各子步骤时限。事务只在旧进程健康、摘要/epoch 匹配且私有提交和进程标记成功之后保存恢复证明；失败收口重新核对实际运行代次与该证明，宿主投影未确认时保留健康旧进程和 RUNNING 私有事实，LastError/Engine Failure 明确记录 RECOVERY_FAILED，不把未同步完成的操作宣称完整回滚。

未通过健康、指针提交、MarkCommitted 或实际代次错配时，原停止与 FAILED 收口保持。原生配置不变的旧进程复用已提交快照和原 epoch，不因宿主同步故障额外重启；总补偿预算耗尽后的 API 观察与故障记账各有独立 2 秒边界，过期 context 不能被解释成真实 API 故障。

复用真实 Store、现有 Apply 夹具和单个启动观察接缝，回归实际 2 秒宿主 CAS 超时、补偿 context 预算、替换/未替换两类健康旧进程存活、失败可重试，以及不健康进程仍停止。真实 Manager/短时 Go 子进程核对过期 API 探测与独立进程事实；真实私有快照加窄进程边界验证预算耗尽后的失败收口。Core Intent 从原夹具抽取为共享测试输入，不复制字段或放宽 Store 的 0700/摘要要求。PLG03/04 的取消等待、启动清理、宿主 epoch 与端口预检另行继续。
