# 基础监控

`monitor.basic` 使用宿主 `metrics.read:self` 读取结构化瞬时计数器，插件保持默认网络与进程沙箱。它不直接读取宿主 `/proc`，不写系统配置，也不把时序数据写进持久状态或事件日志。

默认保留 300 个细采样点和 360 个粗采样点，分别约 5 分钟和 1 小时。CPU/网络/磁盘速率通过相邻有效采样差分；首次采样、重置、时间未推进和接口变化用 unavailable/null 表示。粗历史只平均有效值，空区间不会补假数据。

五个概览小组件使用当前 Web Shell 的 stat/series 格式；详情页通过 MessagePort 调用本插件只读操作，支持主题、暂停与历史范围切换。显示的宿主时间与当前状态用于区分有效采样和保留历史。阈值只影响卡片健康颜色，当前不产生告警或系统操作。

采样只在 Activate 后运行，使用 SDK 跟踪的后台任务；宿主恢复时重复 Activate 保留当前后台代次与历史，Deactivate/Stop 取消并回收。历史 epoch 由实例随机种子与进程内增量组成，保持 JSON 安全整数范围；新实例不会固定从 1 重新开始。改变历史容量、粗采样间隔或过滤条件会重建易失历史；阈值调整保留历史。

验证：构建机单测/race/vet、SDK 生命周期回收与并发重复激活、包清单、签名/验签和桌面/小屏/深色浏览器检查已通过。两台 VPS 的宿主指标来源已做只读交叉检查；测试机上的真实安装、动态 UID 沙箱及活后台进程的宿主卸载回收已通过。真实试跑还发现 SDK 拒绝重复 Activate 导致读取返回 503，已修正并通过受影响包 race 回归。

MON-04 最新真机验收已走通七个读取、历史、五个小组件、真实 Shell → 插件浏览器、停用及旧 PID 回收。24 秒实测 RSS 峰值约 18.1 MiB、FD 峰值 10、任务峰值 6、平均 CPU 0.088%–0.127%，满足声明预算。浏览器覆盖真实登录、快照、历史切换、暂停/继续、移动布局与小组件，无模拟后端。

重新启用会产生新的真实 PID，但该次验收发现旧实现把 history epoch 从 1 重新计数；现已修正实例种子并通过监控/SDK/嵌入 Shell 的 race、vet 回归。第五次试跑后已停止本验收序列，修正后的真机重新启用 epoch 尚未复验，MON-04 仍不标完整完成。
